# 基线说明（实验04）

## 一、上游选型

| 项 | 值 |
| --- | --- |
| 训练库 | scikit-learn |
| 上游地址 | https://github.com/scikit-learn/scikit-learn |
| 许可证 | BSD-3-Clause |
| 界面库 | Streamlit |
| 上游地址 | https://github.com/streamlit/streamlit |
| 许可证 | Apache-2.0 |
| 数据集 | UCI Wine（经 `sklearn.datasets.load_wine`） |
| 数据许可证 | **CC BY 4.0**（注意：与代码许可证是两回事） |

**为什么是「库」而不是「完整应用」**：
实验04 的两个项目都是**库**，不是可以直接换名提交的成品网站。
这跟实验03（Shlink 本身就是个完整服务）不一样。
所以本项目的"基线"其实是**工具链**，而不是一个现成的应用——
界面、Schema、训练脚本、模型卡、测试和自主功能全部由本人实现。

**为什么选 Wine**：
- sklearn 自带，**不用联网下载**，断网也能复现；
- 178 条 × 13 个数值特征 × 3 类，CPU 上几秒训完，适合课堂；
- 纯数值，不用处理类别列，可以把精力放在 Pipeline 和工程化上；
- 缺点也很明确：样本太少，指标波动大——这点必须写进限制，不能藏。

**为什么不用 `>=` 写依赖**：
版本会漂。`requirements.txt` 里写的是**本机实际安装到的版本**，
这样别人复现时拿到的是一套验证过的组合，而不是"今天的最新版"。

## 二、开发前必须先定下来的事

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 任务类型 | **多分类**（不是回归） | Wine 的标签是 3 个离散类别，不能用 MAE/RMSE/R² |
| 主指标 | **macro F1** | 三类不均衡，macro 对每类同等看待 |
| 划分方式 | 分层随机划分，测试集 25% | 保证每类在测试集里都有足够样本 |
| 是否需要分组划分 | **不需要** | 每行是一个独立酒样本，不存在"同一主体多行" |
| 随机种子 | 42（写死） | 保证任何人在任何时间跑出同样结果 |
| 预处理位置 | 全部在 Pipeline 内 | 防止数据泄漏 |

## 三、数据泄漏风险清单

| 风险 | 本项目的处理 |
| --- | --- |
| scaler / imputer 在划分前拟合 | Pipeline 内处理，`cross_validate` 每折只在该折训练部分拟合 |
| 同一主体跨训练/测试集 | 不适用。Wine 每个样本互相独立；判断依据写在 `src/shuju.py` 的注释里 |
| 反复用测试集选模型 | 代码结构禁止：`zui_zhong_pingjia()` 只在训练流程末尾调用一次 |
| 特征含标签信息 | 13 个特征都是化学检测值，不含品种信息 |

## 六、边界与不做什么

- 不做图像/文本分类（Wine 是纯数值表格数据）。
- 不做超参数搜索（GridSearchCV）。本实验的重点是 Pipeline 工程化，
  加一层网格搜索会让"两算法同协议比较"变复杂，收益不大。
- 不做概率校准、不做分布外检测、不做漂移监控——都写在模型卡的已知限制里。
- 不接收用户上传的模型文件（pickle 反序列化会执行代码）。
