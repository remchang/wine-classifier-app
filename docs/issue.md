## Issue #1 任务定义与数据基线

**标签**：`数据` `设计`

### 要解决的问题

先定义清楚"一个样本是什么、正类是什么、误报和漏报哪个更贵"，再动手写代码。
不然训出来的分数没有意义。

### 结论

| 项 | 决定 |
| --- | --- |
| 任务类型 | 多分类（3 类），**不是回归** |
| 一个样本 | 一瓶酒的 13 项化学检测结果 |
| 标签 | 该酒所属栽培品种（数据集自带） |
| 主指标 | **macro F1**（不是 accuracy） |
| 误报 vs 漏报 | 若按品种分档定价，误报更贵 → 更看重 Precision；若是筛查问题酒，漏报更贵 → 更看重 Recall。本实验无真实业务代价，用 F1 做平衡 |
| 数据集 | UCI Wine，CC BY 4.0，经 `load_wine()` 使用 |

- [x] 模型卡初稿完成（`model_card.md`）
- [x] Schema 检查：178 行 / 13 特征 / 3 类，无缺失、无整列空
- [x] 数据来源与许可证记录在 `NOTICE.md`

## Issue #2 基线模型与划分策略

**标签**：`核心功能`

### 要做什么

完成分层划分，训一个最简基线，确认没有明显泄漏。

### 关键决策

- **分层划分**（`stratify`）：wine 三类 59/71/48，不分层时小类可能在测试集里只剩一两个。
- **不分组划分**：每行是独立酒样本，不存在"同一主体多行"。
- **随机种子写死 42**：保证可复现。
- **预处理全部进 Pipeline**：`cross_validate` 每折只在该折训练部分拟合，
  从结构上杜绝"scaler 在全量数据上拟合"这个经典泄漏。

### 验收条件

- [x] 划分可复现（同种子两次结果一致）
- [x] 训练集与测试集无重叠
- [x] 两类比例接近（分层生效）
- [x] 基线 Pipeline 能直接吃原始输入 `predict`

## Issue #3 两种算法比较与主指标解释

**标签**：`核心功能` `评价`

### 要做什么

在**相同训练折、相同主指标**下比较逻辑回归与随机森林，
用交叉验证选优，测试集**只评一次**。

### 报什么指标

- Accuracy
- Precision / Recall / F1，**macro 和 weighted 各报一份**，并说明平均方式
- 混淆矩阵
- 每类明细（precision / recall / f1 / support）
- 交叉验证的均值 **和标准差**都报（只报均值会掩盖稳定性差异）

### 验收条件

- [x] 按 macro F1 的均值选优，选择过程可复核

## Issue #4 模型保存、元数据与推理应用

**标签**：`核心功能` `应用`

### 要做什么

保存**完整 Pipeline**（不是分开存 scaler 和模型），
并写 `model_meta.json`；再由 Streamlit 加载做实时预测。

### 元数据里放什么

训练时间、scikit-learn 版本、特征名与顺序、标签映射、主指标、
交叉验证结果、测试集结果、数据 SHA256、模型 SHA256、Git Commit。

### 加载时校验什么

1. scikit-learn **主版本**是否一致（不一致直接拒）
2. 元数据里的特征顺序 vs Pipeline 里的 `feature_names_in_`
3. 标签映射是否存在

**为什么这么严**：pickle/joblib 反序列化不保证跨版本兼容；
特征顺序错乱会让预测**静默出错**——不报错、但结果全错。宁可拒加载。

### 验收条件

- [x] 保存前后同一 fixture 的预测完全一致（含概率）
- [x] 元数据里的 SHA256 能对上真实文件
- [x] 缺元数据或多特征名不匹配时拒绝加载
- [x] Web UI 可输入并实时预测，不需要 Notebook

## Issue #5 自主功能：置信度阈值 + 批量预测

**标签**：`自主功能`

### 用户价值

- **置信度阈值**：模型有把握的自动判定，没把握的转人工，避免"硬给一个答案"。
- **批量预测**：一条条填表单太慢，支持上传 CSV 并导出结果。

### 为什么这两个算"自主功能"而不是换个模型名字

指导书要求："自主功能有评价证据，不只是换模型名称。"
所以两项都提供了**量化或案例证据**：

| 功能 | 证据 |
| --- | --- |
| 置信度阈值 | 「阈值分析」页用测试集算出 8 个阈值下的覆盖率与自动判定准确率，趋势可验证 |
| 批量预测 | 自动化测试故意弄坏第 3、5 行，断言其余 8 行照常出结果且行号正确 |

### 验收条件

- [x] 阈值升高时覆盖率单调不增（有测试断言，防止逻辑写反）
- [x] 阈值 0 时的自动准确率 == 整体 accuracy（定义自洽）
- [x] 批量预测单行的结果与单条预测接口完全一致
- [x] 坏行不导致整批失败，行号与原因都报出来
- [x] 结果可下载 CSV
